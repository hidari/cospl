# fix(sw): HTML だけの変更で Service Worker のキャッシュ版数が上がらない

## 背景

起票時は「HTML だけの変更で `__CACHE_VERSION__` が上がらず、 オフラインの訪問者が古い `/` を使い続ける」と書いた。 読み直すと、 `/` のナビゲーションは network-first で、 オンラインで開くたびにキャッシュの `/` も上書きされる。 オフラインで見えるのは最後にオンラインで見た版なので、 HTML については実害がほぼ無い。

実際に穴があるのは、 名前を変えずに中身を差し替えるファイル (フォント・アイコン・ロゴ・favicon・manifest) だった (2026-10-30 に確認)。

- `/fonts/` は cache-first なので、 フォントを差し替えても、 JS か CSS が変わって SW が入れ替わるまで古いまま
- `/icons/` などは stale-while-revalidate だが、 裏の取得が `event.waitUntil` の外にあり、 SW が止められると更新が書かれない
- `STABLE_PRECACHE` は手書きの一覧で、 CSS が使う `/icons/nd.svg` と `/icons/sb.svg` が入っていない。 オフラインではこの 2 つのタグのアイコンが出ない
- 本番の安定名アセットは `Cache-Control: public, max-age=0, must-revalidate` と ETag を返すので、 HTTP キャッシュは遅れの原因にならない

## 求めること

安定名のファイルを差し替えてデプロイしたとき、 前に来たことがある人には、 最初の 1 回だけ古いものが見えてもよいが、 2 回目の表示からは必ず新しいものが見えること。

対象外: HTML (network-first で足りている)、 ハッシュ付きの JS と CSS (名前が中身で変わる)、 オフラインのあいだに新しいものを届けること。

## 比べた案

- A: `/fonts/` を stale-while-revalidate にする。 最小だが、 更新は表示のついでに起きるので、 precache してあってもまだ表示していないファイルは古いまま残る
- B: フォントを Vite の管理下に移してハッシュ付きの名前にする。 救えるのはフォントだけで、 外から決まった名前で参照されるアイコンや manifest には A が要る
- C: SW の版数に安定名アセットの中身を含める。 どれか 1 つが変われば `sw.js` が変わって SW が入れ替わり、 precache 全体を取り直す。 ブラウザはページを開くたびに `sw.js` の更新を確かめる (`no-cache`) ので、 表示のついでの更新に頼らない。 Hidari さんが C を選んだ

## 決定

- 版数は、 ハッシュ付きの JS と CSS の名前に加えて、 安定名の precache 対象それぞれの中身のハッシュから作る。 `/` (HTML) は bundle に無く、 network-first で足りているので入れない
- 裏での更新 (stale-while-revalidate) を `event.waitUntil` に入れる。 案によらないバグなので一緒に直す
- 以下は Claude の判断:
  - 安定名の precache 対象は手書きの一覧をやめ、 `public/` のファイルから述語で選ぶ。 述語はキャッシュ戦略の判定 (`src/client/sw-strategy.ts`) と同じところに置き、 戦略と precache の対象がずれないようにする。 `nd.svg` と `sb.svg` はこれで precache に入る
  - フォントは cache-first のままにする。 中身が変われば版数が変わり、 新しいキャッシュに取り直されるため
  - 版数は長い名前の連結をやめ、 入力全体の SHA-256 から作る短い 16 進にする
- 実装の細部 (純粋関数の置き場と名前、 テストの形) は計画で決める
